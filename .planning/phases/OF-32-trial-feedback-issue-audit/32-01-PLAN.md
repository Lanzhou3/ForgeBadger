# Trial Feedback Issue Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use test-driven-development for
> audit behavior and verification-before-completion before claiming closure.

**Goal:** Add a maintainer-run read-only command that audits a GitHub trial
feedback issue body with the existing first-user feedback packet audit.

---

### Task 1: Define Issue Audit Contract

**Files:**
- Create: `scripts/audit-trial-feedback-issue.test.mjs`

- [x] **Step 1: Write failing tests**

Tests must prove:

- a completed issue-form body passes as ready for human triage only;
- missing `trial-feedback` label fails;
- incomplete issue-form bodies fail through packet audit errors;
- secret-like content in the raw issue body fails;
- repository and issue number are forwarded to the live fetcher;
- CLI args require `--issue=<number>` and accept `--repo=<owner/name>`.

- [x] **Step 2: Verify red**

Run:

```bash
node --test scripts/audit-trial-feedback-issue.test.mjs
```

Expected red result before implementation:

- `ERR_MODULE_NOT_FOUND` for `scripts/audit-trial-feedback-issue.mjs`.

### Task 2: Implement Issue Audit Command

**Files:**
- Create: `scripts/audit-trial-feedback-issue.mjs`
- Modify: `package.json`

- [x] **Step 1: Fetch issue read-only**

Use `gh issue view <number> --repo <repo> --json number,title,state,labels,body,url`.

- [x] **Step 2: Convert issue-form body**

Map GitHub issue-form `###` sections into the Markdown packet structure already
understood by `auditTrialFeedbackPacket`.

- [x] **Step 3: Preserve safety boundaries**

Include the raw issue body in audit input so secret-like content outside mapped
fields is still rejected. Always return `gateClearingEvidence: false`.
