# Task Packet And Work Queue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert Project Manager work items into launchable AI CLI task packets with acceptance criteria, verification guidance, evidence expectations, and safe session linkage.

**Architecture:** Keep task packets as bounded projections of existing Project Manager work items. Gateway derives task-packet DTOs from tenant-scoped work items and same-project sessions; Web renders the work queue and handoff context. Starting a task creates or reuses one idle same-project session and stores only bounded context metadata. OpenForge never writes task-packet prompts into terminal input automatically and never stores raw terminal scrollback in SQLite.

**Tech Stack:** Express, TypeScript, SQLite repositories, zod, Next.js, TanStack-style API client helpers, Vitest, node:test.
