# Trial Feedback Packet Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use test-driven-development for
> the packet audit helper and verification-before-completion before claiming
> closure.

**Goal:** Add a local audit command that rejects generated drafts, placeholders,
and secret-like content before a Markdown feedback packet enters maintainer
triage.

---

### Task 1: Define Audit Contract With Tests

**Files:**
- Create: `scripts/audit-trial-feedback-packet.test.mjs`

- [x] **Step 1: Write failing tests**

Tests must prove:

- generated feedback drafts fail audit;
- a completed redacted packet passes as ready for human triage only;
- packets with token/key-shaped content fail;
- CLI args parse packet path and `--json` while rejecting bad usage.

- [x] **Step 2: Verify red**

Run:

```bash
node --test scripts/audit-trial-feedback-packet.test.mjs
```

Expected red result before implementation:

- `ERR_MODULE_NOT_FOUND` for `scripts/audit-trial-feedback-packet.mjs`.

### Task 2: Implement Audit Helper

**Files:**
- Create: `scripts/audit-trial-feedback-packet.mjs`
- Modify: `package.json`

- [x] **Step 1: Audit sections and fields**

Require core packet sections, filled field values, completed reproduction
steps, expected behavior, actual behavior, diagnostics status, triage routing,
terminal evidence summaries, support summaries, and `Redaction review
completed: yes`.

- [x] **Step 2: Preserve gate boundary**

Always return `gateClearingEvidence: false`; passing audit only means ready for
maintainer triage.

- [x] **Step 3: Reject secret-like content**

Reject obvious bearer tokens, `sk-*` keys, `openforge.token`, OpenForge secret
env assignments, and generic key/token/password/private-key assignments.
