> **For agentic workers:** REQUIRED SUB-SKILL: Use systematic-debugging to
> identify the documentation contradiction, test-driven-development for the
> validator regression, and verification-before-completion before claiming
> closure.

**Goal:** Keep first-user diagnostics guidance tokenless and machine-verified.

**Root cause:** Phase 24 validated feedback intake files, but not the runbook.
`docs/TRIAL-RUNBOOK.md` still told users to read browser Local Storage and use
the `openforge.token` value in a curl request.

- Modify: `scripts/validate-trial-feedback-intake.mjs`

- Settings diagnostics export path;
- `Export diagnostics JSON` action;

- [x] **Step 2: Reject token fallback wording**

The validator must reject non-negated runbook lines containing:

- browser developer tools;
- `Read Local Storage`;
- `openforge.token`;
- `authorization: Bearer <token>`.

- [x] **Step 3: Update runbook**

Replace the first-user curl/token instructions with Web Settings export steps
and a maintainer-only local API fallback.
