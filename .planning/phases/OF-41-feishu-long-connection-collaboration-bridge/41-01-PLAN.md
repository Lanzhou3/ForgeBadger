# Feishu Long-Connection Collaboration Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide a Feishu bot long-connection collaboration entrypoint that can route bounded OpenForge commands without public callback ingress.

**Architecture:** Keep Feishu long-connection handling as an authenticated Gateway-side receive path for a local worker. The Gateway normalizes SDK-style `im.message.receive_v1` events, applies tenant policy, returns bounded reply plans, records reconnect evidence, and rejects terminal input or free-form approval text. Real Feishu SDK connection and outbound bot send remain operator evidence steps outside automated local tests.

**Tech Stack:** Express, TypeScript, SQLite repositories, zod, node:test, local script smoke harness.
