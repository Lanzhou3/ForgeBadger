## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Gateway PM routes | Authenticated but user-controlled PM evidence and ledger query input crosses into Gateway validation. |
| Gateway PM routes -> repository | Route DTOs and authenticated user/project IDs cross into tenant-scoped repository transactions. |
| Repository JSON details -> Web DTO | Stored JSON details are converted into bounded `trace` DTOs and must not leak raw details. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01-01 | Elevation of Privilege | `project-manager.ts` route handlers | mitigate | Preserve `authenticate`, `requireProject(db,userId,projectId)`, and `ProjectManagerRepository(db,userId)` for all evidence/ledger paths; add route tests for cross-tenant non-leak behavior. |
| T-12-01-02 | Information Disclosure | `toLedgerEventDto` and `toEvidenceRefDto` | mitigate | Expose only `pendingActionId` and D-07 trace fields; keep raw `details`, prompt, terminal, provider payload, diff, summary, token, API key, JWT, private key, stdout, and stderr out of serialized responses. |
| T-12-01-03 | Tampering | `ProjectManagerEvidenceRef` normalization | mitigate | Keep strict zod evidence schema and repository allowlist; tests prove unknown fields are rejected or stripped and no route mutation occurs on invalid input. |
| T-12-01-04 | Repudiation | PM ledger/audit transaction | mitigate | Preserve existing repository transaction model so projection, evidence refs, ledger event, and audit row remain atomic per D-08. |
| T-12-01-SC | Tampering | npm/pip/cargo installs | accept | No package installs are planned; Package Legitimacy Audit states no install required. |
