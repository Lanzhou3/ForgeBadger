<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored pending action -> Copilot UI | Gateway-stored action input/result becomes visible approval text and commands. |
| URL search params -> Project Manager panel | User-controlled `tab` and `workItemId` choose the visible project tab/detail state. |
| PM ledger/evidence DTO -> React render | Tenant-scoped safe markers become visible trace cells. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-04-01 | Stored XSS | `copilot-chat-panel.tsx` and `ProjectManagerPanel.tsx` | mitigate | Render structured text through React only; do not use raw HTML; long IDs use `break-all` and mono text. |
| T-12-04-02 | Spoofing | PM approval card summary | mitigate | Use fixed templates and action type maps; model-generated prose is not the primary approval summary. |
| T-12-04-03 | Information Disclosure | PM detail/ledger markers | mitigate | Render `trace` DTO and evidence marker fields only; never render arbitrary `details`, raw prompts, terminal output, provider payloads, or full approval diffs. |
| T-12-04-04 | Tampering | URL `workItemId` selection | mitigate | Treat URL selection as UI state only; data remains fetched through existing tenant-scoped Gateway routes. Missing work item shows scoped PM state, not global failure. |
| T-12-04-05 | Denial of Service | Long marker values | mitigate | Use existing compact layouts with wrapping `break-all` for IDs and no viewport-scaled fonts, preventing overflow/overlap. |
| T-12-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs are planned; uses existing shadcn/Tailwind/lucide/Playwright stack. |
</threat_model>
