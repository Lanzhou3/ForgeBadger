<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model tool call -> Gateway prepare tool | Untrusted model-produced structured input enters zod validation. |
| Browser approval -> Gateway approve route | Authenticated user action approves a stored pending action but must not replace payload. |
| Copilot approval -> PM repository | Stored PM proposal crosses into Gateway-owned tenant-scoped PM mutations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02-01 | Tampering | Approval route payload | mitigate | Approval ignores client mutation fields and parses only canonical stored `action.input`; tests attempt replacement payloads. |
| T-12-02-02 | Elevation of Privilege | PM approval helpers | mitigate | Revalidate project and work item visibility through user-scoped repositories before each create/status/evidence mutation. |
| T-12-02-03 | Tampering | Duplicate approvals | mitigate | Preserve `pending -> processing` claim with `updatePendingActionIfStatus`; duplicate or concurrent approvals return 409 and do not execute. |
| T-12-02-04 | Repudiation | PM execution failure | mitigate | PM execution failure updates action to terminal `failed` with safe result code and does not restore pending, satisfying D-04. |
| T-12-02-05 | Information Disclosure | PM action input/result | mitigate | Schemas reject raw prompt/terminal/provider/diff/summary fields; safe trace/result builders include IDs/counts/status only. |
| T-12-02-SC | Tampering | npm/pip/cargo installs | accept | No package installs are planned; all work uses existing zod, repositories, and tests. |
</threat_model>
