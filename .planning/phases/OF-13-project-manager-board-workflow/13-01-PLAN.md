# Phase 13 Plan 01: Board Workflow Backend Contract

## Objective

Create the Gateway and Web API contract that a Project Manager board can use for edit, delete, and bounded batch status movement without bypassing existing status transition, evidence, ledger, audit, and tenant-scope rules.

## Scope

- Add repository methods for work item edit, delete, and batch status update.
- Add project-scoped REST endpoints for those operations.
- Add Web API client types/helpers and i18n labels for the new ledger event types.
- Keep board UI, drag/reorder, and visual Kanban columns for later Phase 13 plans.
- Do not add position/rank schema in this plan.

## Tasks

1. Add failing repository and route tests for:
   - work item edit writes a projection update, `work_item_updated` ledger event, and audit row;
   - delete requires explicit confirmation, writes `work_item_deleted` with bounded target marker, audits, and removes the projection row;
   - batch status updates are limited, duplicate-free, atomic, and use existing transition/evidence guards.
2. Implement repository methods and route handlers.
3. Add Web API client helpers and update ledger event type labels.
4. Update `docs/API.md`.
5. Verify focused backend and Web API/type tests.
