# Provider Health And Identity Web Surface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the Gateway provider readiness contract in the `/models` Web page so users can see actionable provider/model/credential health and Codex subscription identity boundaries.

**Architecture:** Keep the Web page provider-first. Add a typed API helper for `POST /api/v1/model-providers/:id/readiness`, a Provider Health panel in the existing right-side workflow column, and a Codex identity card that uses the existing subscription status endpoint. The panel uses selected provider/model/credential/apply-target state and never displays plaintext credentials or raw provider payloads.

**Tech Stack:** Next.js App Router client component, React, TanStack Query, TypeScript, Playwright E2E, existing OpenForge API client and i18n.
