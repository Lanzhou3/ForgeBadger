# Model Provider Readiness Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Gateway-owned model-provider readiness contract that explains provider, credential, model, target adapter, and remote model-list health without leaking credentials or wiring Codex into provider config.

**Architecture:** Add a focused readiness service under Gateway that evaluates a selected Provider Profile against a target adapter and optional model/credential selection. The route returns structured readiness checks, a stable code, actionable remediation steps, and optional safe lightweight remote model-list evidence where supported. The existing provider CRUD/apply/sync contracts remain unchanged; Codex keeps returning a managed-elsewhere readiness result instead of accepting provider API-key/model injection.

**Tech Stack:** Express, TypeScript, zod, `node:test`, existing ModelProviderRepository, existing `fetchProviderModels` safe HTTPS model-list helper.
