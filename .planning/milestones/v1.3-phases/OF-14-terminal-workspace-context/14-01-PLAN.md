# Gateway Workspace Context Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add project-scoped Gateway APIs for safe workspace file tree listing and bounded text file reads.

**Architecture:** Keep workspace context Gateway-owned and read-only under `/api/v1/projects/:id/workspace/*`. Reuse `ProjectRepository(db, userId)` for tenant scoping and `safeResolve` / `validateProjectRoot` for path containment. Add a small service that never writes file content, terminal output, or evidence blobs to SQLite.

**Tech Stack:** Express, TypeScript, zod, node:test, SQLite test database, existing OpenForge response envelope.

### Task 2: Workspace Context Service

**Files:**
- Create: `packages/gateway/src/services/workspace-context.ts`

- [x] **Step 1: Implement a read-only service**

Add:
- `listWorkspaceTree(projectRoot, input)` with `path`, `depth`, and `limit`;
- `readWorkspaceFile(projectRoot, input)` with bounded UTF-8 text content;
- shared path normalization that returns project-relative POSIX paths;
- `lstat` symlink checks before traversal/read;
- maximum tree depth, entry count, and preview byte limits.

- [x] **Step 2: Keep terminal and evidence boundaries intact**

Do not add database writes, terminal capture reads, or evidence mutation here. This plan only returns bounded project file context to the caller.

### Task 3: Project Routes

- [x] **Step 1: Add query validation**

Add zod schemas for:
- `GET /:id/workspace/tree?path=&depth=&limit=`

- [x] **Step 2: Add authenticated project-scoped route handlers**

For each route:
- authenticate via existing project routes middleware;
- lookup with `new ProjectRepository(db, userId).getById(req.params.id)`;
- return 404 for missing or cross-tenant projects;
- call the workspace context service;
- return canonical envelopes.
