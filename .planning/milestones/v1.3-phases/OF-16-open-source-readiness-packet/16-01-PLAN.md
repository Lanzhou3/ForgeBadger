> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close Phase 16 by making OpenForge's open-source entry points explicit, safe, and caveat-preserving.

Add root-level contributor/security entry points, extend GitHub issue templates for safe feedback, document the MIT license rationale, and update planning/readiness docs without changing Gateway or Web runtime behavior.

**Tech Stack:** Markdown, GitHub issue form YAML, existing `.planning` GSD files.

**Files:**
- Modify: `README.md`
- Create: `CONTRIBUTING.md`
- Create: `SECURITY.md`
- Create: `docs/OPEN-SOURCE-READINESS.md`

- [x] **Step 1: Document license rationale**

Add an open-source readiness doc that states OpenForge uses MIT because the project is a local-first developer tool intended for broad local use, forks, adapters, and self-hosted experimentation. Also record what MIT does not change: no hosted support promise, no warranty, and no permission to publish secrets or third-party credentials.

- [x] **Step 2: Add contribution guide**

- [x] **Step 3: Add root security policy**

Create a root `SECURITY.md` that links the deeper security model, states what to report privately, what not to paste publicly, and clarifies local/self-hosted support boundaries.

- [x] **Step 4: Update README entry points**

Link `CONTRIBUTING.md`, `SECURITY.md`, and `docs/OPEN-SOURCE-READINESS.md` from README.
