- D-01: Task 1, Task 2, and Task 3 keep Phase 5 docs-only and prohibit runtime route, migration, Web UI, terminal transport, package, or lockfile changes.
- D-02: Task 1 and Task 2 preserve OpenForge as a local-first AI CLI control plane and treat remote execution as an explicit user-owned target extension.
- D-03: Task 1, Task 2, and Task 3 keep hosted collaboration, cloud deployment, billing, telemetry, hosted marketplace, and cloud workers deferred.
- D-04: Task 1 and Task 2 preserve existing beta caveats instead of using remote architecture as a shortcut to close them.
- D-05: Task 1 documents explicit `local` and user-managed `ssh` execution targets.
- D-06: Task 1 documents project target binding and session launch target inheritance.
- D-07: Task 1 documents SSH target plus remote agent over stdio and rejects raw `ssh host "tmux ..."` wrappers.
- D-08: Task 1 and Task 2 keep browser traffic mediated by Gateway and reject direct browser-to-SSH.
- D-09: Task 1 and Task 2 preserve the existing terminal WebSocket message contract.
- D-10: Task 1 documents remote agent ownership of remote path validation, dependency discovery, tmux lifecycle, and cleanup.
- D-11: Task 1 requires typed remote-agent operations and rejects generic arbitrary shell command APIs.
- D-12: Task 1 and Task 2 preserve tmux-backed terminal persistence and prohibit terminal scrollback, raw transcripts, or remote command output in SQLite.
- D-13: Task 1 and Task 2 preserve authenticated WebSocket/session attach-token terminal input authority and exclude Copilot/Feishu direct remote terminal control.
- D-14: Task 1 requires SSH fail-closed behavior and rejects `StrictHostKeyChecking=no`.
- D-15: Task 1 requires host-key pinning or preconfigured fingerprint and hard failure on host key mismatch.
- D-16: Task 1 and Task 2 prefer `ssh-agent` or selected key path and defer private key import unless encryption, passphrase, deletion, and security review are designed.
- D-17: Task 1 and Task 2 prohibit plaintext SSH password storage in the first remote execution release design.
- D-18: Task 1 and Task 2 keep remote CLI account state on the remote host and prohibit copying local provider keys to remote targets.
- D-19: Task 1 requires remote `safeResolve`/realpath checks against allowed roots on the remote host.
- D-20: Task 1 requires explicit allowed roots per SSH target.
- D-21: Task 1, Task 2, and Task 3 keep Codex app-server Web prompt and `/turn` input disabled until retention, consent, rate limiting, model usage, and security review are designed.
- D-22: Task 1 and Task 2 exclude remote Codex app-server control-plane support from the first remote architecture package.
- D-23: Task 1, Task 2, and Task 3 document and verify stable remote failure codes for host key, SSH, remote agent, tmux, CLI, path, launch, and terminal attach failures.
- D-24: Task 1, Task 2, and Task 3 require bounded redacted diagnostics and prohibit private keys, passphrases, raw SSH stderr, bearer tokens, attach tokens, terminal transcripts, and sensitive full paths.
- D-25: Task 2 defines additive local-safe rollback, remote launch disablement, nullable/default-local future migration rules, and ignorable remote target records.
- D-26: Task 1 documents staged future delivery: target registry/test, remote dependency/project discovery, remote terminal sessions, and hardening/release evidence.
- D-27: Task 1 keeps WSL as optional explicit SSH smoke only and preserves physical Windows/WSL local terminal caveat evidence.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser to Gateway HTTP/WebSocket | Authenticated but untrusted client requests and terminal input reach Gateway; browser must never connect directly to SSH. |
| Gateway to SSH target | Gateway crosses from local control plane into a user-owned remote host over SSH and must fail closed on host identity and auth failures. |
| Gateway to remote agent stdio | Structured remote-agent messages cross a protocol boundary and must be versioned, schema-validated, and method-allowlisted. |
| Remote agent to remote filesystem/tmux/CLI | Remote path, dependency, and tmux operations run where symlinks and CLI auth state actually exist. |
| Gateway diagnostics/reporting to user/support | Operational evidence may be shared and must not leak credentials, raw SSH stderr, terminal transcripts, attach tokens, or sensitive paths. |
| Web/Codex app-server control plane to `/turn` | Codex turn input remains disabled unless retention, consent, rate limiting, model usage, and security review are complete. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| REM-T01 | Spoofing | SSH host identity | mitigate | Threat model requires host key pinning, no `StrictHostKeyChecking=no`, no `UserKnownHostsFile=/dev/null`, and `host_key_mismatch` as a hard user-action error. |
| REM-T02 | Information Disclosure | SSH credentials | mitigate | Prefer `ssh-agent` or key path; forbid plaintext SSH passwords; defer private key import unless encryption, passphrase, deletion, and security review are designed. |
| REM-T03 | Tampering / Elevation of Privilege | SSH/tmux launch path | mitigate | Reject raw `ssh host "tmux ..."` wrappers and generic shell APIs; require typed remote-agent operations and parameterized arguments. |
| REM-T04 | Tampering / Denial of Service | Remote agent protocol | mitigate | Require protocol version handshake, schema validation, method allowlist, message-size handling, unknown-method rejection, and release blocker status for unresolved high-severity protocol abuse. |
| REM-T05 | Tampering / Information Disclosure | Remote path validation | mitigate | Require remote `safeResolve`/realpath against explicit target allowed roots; reject traversal, encoded traversal, and symlink escapes with `remote_path_denied`. |
| REM-T06 | Denial of Service | Terminal input over remote transport | mitigate | Preserve existing attach-token auth, one active terminal WebSocket per session, heartbeat, message size limit, and 50 terminal input messages per second per connection. |
| REM-T07 | Elevation of Privilege | Tenant target/project/session binding | mitigate | Require user-scoped target ownership checks, project target binding at create/import, session target copy at launch, and no target switching at attach time. |
