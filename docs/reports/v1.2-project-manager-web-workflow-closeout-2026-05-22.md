## Redaction Rules

Acceptable Project Manager evidence references are short pointers:

- docs paths such as `docs/TRIAL-CHECKLIST.md`;
- test file names such as `project-manager.spec.ts`;
- report paths under `docs/reports/`;
- issue or PR identifiers such as `OF-123` or `PR-42`;
- short command names or smoke labels.

Do not paste or attach forbidden content:

- raw terminal transcripts;
- Feishu message bodies;
- provider payloads;
- API keys;
- JWTs;
- private keys;
- attach tokens;
- unrelated project secrets;
- browser auth token values;
- raw provider or callback bodies.

Ledger rows must remain safe markers only. They may show event type, work item
title or ID, status, evidence count, Feishu reference count, and timestamp. They
must not show raw manual reasons, evidence reference lists, terminal output,
Feishu bodies, provider payloads, or secret-bearing details.

## Closeout Decision

OpenForge v1.2 Project Manager Web Workflow is ready for first-user trial as a
local-first project control workflow:

- goal and work item operations are browser-accessible;
- evidence references are bounded pointers, not raw content;
- ledger review is safe and filterable;
- focused regressions cover evidence failure, ledger failure, and evidence-free
  `done` behavior;
- trial and support docs describe the evidence and redaction boundaries.

Do not broaden this closeout into remote runtime, live provider, physical
Windows/WSL, real Feishu callback, or completed first-user feedback claims until
those rows are cleared with real evidence.
