## 零、MVP-0 硬范围（2026-04-26）

MVP-0 的目标是验证 OpenForge 的核心产品承诺：**用 Web 控制台管理本地 Claude Code CLI 会话，并在断连/重启后保持会话可恢复**。

### MVP-0 用户闭环

用户必须能在 5 分钟内完成：

1. 登录或注册。
2. 创建或导入本地项目。
3. 选择内置 Claude Code 规范模板。
4. 注入 `.claude/CLAUDE.md` 等配置文件。
5. 创建 Claude Code 会话。
6. 在浏览器终端中与 Claude Code 交互。
7. 刷新浏览器或重启 Gateway 后恢复会话。

### MVP-0 包含

- F0 用户认证与基础多租户隔离。
- A/I 项目创建、导入、扫描、冲突检测、配置注入。
- Claude Code adapter。
- 内置 Claude Code 模板。
- B2/B3/B5 会话创建、内置终端、状态监控。
- API key 加密存储，以及显式 host environment 凭据模式。
- Gateway 创建 tmux 会话、node-pty attach、WebSocket terminal。
- WebSocket 认证、会话归属校验、单连接替换、心跳、消息大小限制、基础输入限流。

### MVP-0 不阻塞项

以下能力进入 MVP-1 或之后，不得阻塞 MVP-0：

- OpenCode / Codex adapter。
- 完整 Agent 编辑和编排。
- 完整 Skill 编辑和安装市场。
- Template 版本管理、同步和市场。
- Dashboard 统计分析。
- 团队/RBAC/审计增强。
- 费用统计和历史快照。

### MVP-1 范围

MVP-1 在 MVP-0 通过 Gate D 后展开：

- Agent CRUD 和 Claude 格式配置生成。
- Skill 启用/禁用和注入。
- Template 列表/编辑/预览。
- Model 管理和 Key 轮换 UX。
- Dashboard 健康检查。
- Session 分组/搜索和更细状态事件。

## 一、产品定位

**一句话：** 新一代 AI 编程 IDE 控制平台。兼容主流 AI 编码 CLI（Claude Code / OpenCode / Codex 等），集成项目初始化、已有项目导入、多会话管理、Agent 管理、Skill 管理、规范注入于一体。

**核心价值：** 在一个平台上完成从项目创建/导入 → 规范注入 → 会话管理 → 编码协作的完整 Vibe Coding 流程。

**产品形态：** Gateway 服务 + Web 控制台
- 后台服务，管理所有 AI CLI 实例
- 浏览器访问 Web 控制台，支持 PC / 手机随时随地操作
- CLI 工具全在本地跑，API 密钥不上传，安全合规

## 二、用户场景

### 场景 1：新项目启动
开发者创建新项目 → 选择 AI 工具 → 选择规范模板 → 一键生成所有配置文件 → 开始编码

### 场景 2：已有项目导入
开发者有现有项目 → 平台扫描识别 AI 工具类型 → 一键注入规范配置 → 接管到平台管理

### 场景 3：多项目并行
同时管理 10+ 项目 → 每个项目用不同 AI 工具 → 在一个平台查看所有会话状态 → 快速切换

### 场景 4：个人开发者尝鲜
独立开发者只想快速切换 AI 工具 → 打开平台就能看到所有会话 → 一键操作

### 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| Gateway | Node.js / Python（待定） | 后台服务，管理 CLI 实例 |

### B3 内置终端说明

终端渲染（xterm.js）和 WebSocket 传输是成熟技术。主要验证点：
- 断线重连：网络断开再连回来，终端状态可恢复
- tmux 会话生命周期：Web 关了 tmux 不能死，下次打开还能接上

**开发前做 POC 验证，能跑通就干，跑不通换方案，不提前过度设计。**

## 七、开发依赖关系

```
Day 1 必须先做：
  G0 用户认证 + 多租户（否则所有数据层要返工）

可并行开发：
  A 项目初始化 ──┐
  I 项目导入     ├── 这三块互不依赖，可并行
  D Skill 管理  ──┘

有双向依赖：
  A3 跨工具配置生成 ↔ E3 模板编辑
  → 建议同步开发

独立模块：
  B3 tmux adapter 可完全独立开发，不阻塞其他
```

### 开发风险预警 Top 5

1. **G0 认证是基石** — 必须 Day 1 先做，否则所有数据层要返工
2. **B3 终端 POC** — 断线重连和 tmux 生命周期需提前验证
3. **A3 跨工具配置** — 三套格式同时做风险高，先打透 Claude Code 再扩展
4. **A3 ↔ E3 双向依赖** — 建议同步开发，避免阻塞
5. **MVP 工时偏紧** — 实际 17-20 天，比原估算 14 天多 21%-43%

## 十、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| AI CLI 格式变更 | 配置生成引擎失效 | 适配器模式，每种 Agent 独立 adapter |
| MVP 功能过多 | 延期交付 | 严格按 P0 范围执行，P1/P2 不提前 |
| 社区冷启动 | 无人使用 | 内置高质量模板（Harness Engineering），开源 + 文档 |
| 项目导入兼容性 | 识别错误/注入失败 | 冲突检测 + 用户确认 + 回滚机制 |

## 十一、错误处理规范

### 错误分类

| 类型 | 示例 | 处理策略 |
|------|------|----------|
| 用户操作错误 | 项目路径不存在、模板选择为空 | 前端校验拦截 + 友好提示 |
| 配置注入失败 | 文件权限不足、文件冲突 | 中止操作 + 回滚已变更 + 错误报告 |
| 终端断连 | 网络中断、tmux 会话崩溃 | 自动重连（3 次）+ 手动恢复入口 |
| API 调用失败 | API Key 无效、端点不可达 | 降级提示 + 切换备用模型 |
| CLI 进程卡死 | Claude Code 无响应 | 超时检测（5min）+ 强制终止 + 状态清理 |
| 模型切换失败 | 模型不存在、配额用尽 | 回退到当前模型 + 错误提示 |

### 回滚机制

- 配置注入前自动备份目标目录
- 注入失败自动回滚到备份状态
- 用户可手动触发回滚

## 十二、安全规范

| 项目 | 方案 |
|------|------|
| API Key 存储 | 环境变量注入，不落盘明文，Gateway 内存中管理 |
| 用户密码 | bcrypt 加密存储 |
| 多租户隔离 | 用户级数据隔离（user_id 外键），文件路径隔离 |
| 会话安全 | WebSocket 连接鉴权，tmux 会话用户级隔离 |
| 文件访问控制 | Gateway 以普通用户运行，限制文件系统访问范围 |
