# ForgeBadger FB-01 — 机器人宠物造型初稿

使用本机 Blender 5.2.1 LTS 建模及 Cycles 渲染，无外部纹理或素材。

设计：大头小身体、陶瓷白外壳、深色面罩、青色发光眼睛与终端提示符、橙色天线和耳罩；一侧机械手抬起打招呼。沿用当前像素宠物的机器人特征与默认青色品牌点缀。

## 文件

- `forgebadger-fb01.blend`：可编辑场景，包含机器人、相机和摄影棚灯光。
- `forgebadger-fb01.glb`：仅机器人，内置 PBR 材质，无外部资源依赖。
- `hero.png`：三分之四视角，1200 × 1200。
- `front.png` / `rear.png`：正面与背面，900 × 1100。
- `pet-transparent.png`：透明背景宠物素材，640 × 640。
- `build_robot.py`：从几何体创建整个场景、导出模型并渲染四张图片。
- `model-info.json`：生成时记录的网格数、三角形数、文件大小。

## 使用与范围

Blender / GLB 是可编辑的静态造型源文件；平台现已使用它渲染的透明 WebP 精灵图替换宠物。模型有头、身体、双臂和双腿的独立父级，方便后续做刚体动画；当前没有骨骼绑定或动画片段。Blender 中 Z 向上、机器人面向 -Y；GLB 自动转为 glTF 坐标约定。

前端只播放预渲染精灵图，不加载 GLB，不创建 WebGL 上下文。GLB 的约 3.2 万三角形不参与浏览器实时渲染。

## 重建

在新的 Blender 场景中，切换到 Python 控制台，粘贴运行（脚本会清空当前场景）：

```python
import runpy
runpy.run_path('/Users/lanzhou/Project/ForgeBadger/design/robot-pet-v1/build_robot.py', run_name='__main__')
```

本机通过已打开的 Blender 界面执行。沙箱内后台进程在 Metal 设备初始化时崩溃，因此不把后台运行列为已验证路径。

## 前端动作素材

`render_sprites.py` 在 Blender 中从源文件副本追加独立场景，输出 7 张 192 × 192 RGBA 帧；保留用户当前场景，不覆盖源文件。用与重建脚本相同的 `runpy.run_path` 方式执行该脚本即可。然后在仓库根目录运行：

```bash
node design/robot-pet-v1/pack_sprites.mjs
```

打包使用 Next 已有的 sharp 依赖，不新增运行时依赖。输出到 `packages/web/public/pets/fb01/`：

| 文件 | 帧 | 大小 |
| --- | --- | ---: |
| stand.webp | 站立、眨眼 | 8,956 字节 |
| walk.webp | 拖动行走 2 帧 | 9,494 字节 |
| sit.webp | 坐着打字 2 帧、眨眼 | 8,854 字节 |

大小由 `sprite-info.json` 记录。总下载 27,304 字节；全部 RGBA 像素约 0.98 MiB（不含浏览器对象、合成层及驱动开销）。默认只加载站立图，其余动作按状态加载；同组切帧只移动图片，不再请求资源。显示尺寸 88 CSS px。

`RobotSprite.tsx` 显示素材，加载中暂用站立帧，失败时回退本地像素机器人。`RobotWidget` 继续管理点击、拖拽、四角吸附、眨眼、8 秒后坐下、通知与聊天。`useRobotMotion` 跟踪页面可见性和系统减少动态效果偏好：不可见或减少动态效果时停止装饰动作定时器。通知生命周期仍按原逻辑执行。

白色外壳、青色眼睛和橙色配件已烘焙进素材；页面主题色继续用于通知光晕。当前不是自由旋转的 3D 宠物。

拖动朝向按最近一次超过 2 CSS px 的水平位移更新：原始素材朝左，向右时镜像；小幅位移累计到阈值后也可转向。位置仍根据按下点计算，避免反向时跳位。纯垂直移动不改变朝向。


## 宠物选择设置

控制台 `/settings` 的主题卡片下方提供「宠物选择」，当前只有机器人，并显示静态预览与选中状态。点击选项会保存到当前浏览器的 `forgebadger.pet`；保存成功/失败有明确反馈。设置卡片与悬浮宠物通过同一偏好存储读取选择，兼容同页和其他标签页的更新；缺失、无效或不可读的旧值回退为机器人。该偏好不写入项目配置或 Gateway 数据库，也不跨设备同步。
